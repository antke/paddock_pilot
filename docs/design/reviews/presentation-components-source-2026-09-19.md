# Presentation components — 19 September 2026

Scope: ten badge/avatar/horse-card owners, their direct callers and relevant lower global recipes. Impeccable audit/harden applies. Source and local DOM evidence only; no browser, live image download, backend writes, authentication, global CSS, metric/progress or coverage edits.

## Confirmed defects and owner corrections

**User image failure left a broken image instead of a fallback.** `UserAvatar` rendered an img whenever `photoUrl` existed and had no error handler. A DOM image-error regression failed before correction. It now remembers the failed URL, renders initials instead, and tries a changed URL. Removing the URL or changing the name updates the fallback. Its decorative `aria-hidden`/empty-alt contract remains, since both current consumers display the person's name beside it.

**User initials split supplementary Unicode characters.** `part[0]` returned half of the first surrogate pair; the actual `𠮷野 花子` regression produced replacement-character + 花. Initials now read complete Unicode code points with `Array.from`, matching the horse avatar's approach; a blank name gets `?` rather than an empty circle. This is code-point safety, not a claim of full linguistic/grapheme-aware initials for every script.

**Arbitrary allergy text inherited an unbreakable badge.** `HorseAllergyBadge` consumed global Badge's nowrap/shrink-0 recipe for unrestricted allergy strings, inside the profile's wrapping badge row. The domain owner now applies `max-w-full`, normal whitespace, anywhere wrapping and left alignment, so the safety text can remain complete instead of extending a single unbreakable badge. No global Badge change or text truncation was introduced. This is a source wrapping correction; actual narrow-screen geometry still needs browser confirmation.

**An active health issue kind label implied urgency without severity.** `HealthIssueKindBadge` previously mapped every active issue to destructive while `HealthIssueStatusBadge` already mapped active to info and severity had a separate low/medium/high mapping. `HorseTimelinePage` uses this kind badge for low and medium issues too, alongside independently chosen timeline severity accents. The active kind now uses info; the high-severity badge remains destructive. Resolved remains secondary. This does not change data status or clinical priority.

Redundant status SVGs in `HealthIssueStatusBadge` and `CareReminderStatusBadge` are explicitly aria-hidden; their full visible status labels remain authoritative. No additional icon treatment was added.

## Intentionally retained and unresolved

- All badge owners consume the global `Badge` recipe and semantic colors. Text communicates state. A completed event/reminder is not styled as an error; cancelled/dismissed/withdrawn states are neutral. High-severity and overdue labels retain exceptional-state colors. No generic palette recoloring was warranted.
- Event date keys are supplied by validated domain records/shared helpers. No fallback “today” was invented for malformed imported dates; invalid external data would require an explicit data-boundary policy, not a silently misleading badge.
- Avatar images are decorative because their actual callers repeat the full name. Adding name alt text would duplicate those names. UserAvatar's forwarded div props still allow an explicit caller override where necessary.
- Horse card title text inherits the shared two-line clamp; full text remains in the DOM/accessibility name and linked cards lead to the full profile. The source review does not establish that two visually similar long registered names remain distinguishable on mobile. That narrow-layout risk is recorded for browser inspection, not automatically treated as a reason to remove every shared title clamp.
- Native checkbox names include horse identity and metadata, useful when multiple horses share similar names. Current form callers supply fieldset/legend and associated group errors; the card does not create a second form or fake checkbox role. The invisible native input delegates its focus treatment to the visible card through the peer recipe.
