## Confirmed active defect and authorized correction

**P2 — Separator orientation styles do not match installed Base UI attributes.** `src/components/ui/separator.tsx` previously selected `data-horizontal`/`data-vertical`. Installed `@base-ui/react/separator` renders `data-orientation="horizontal"` or `"vertical"`, along with `role="separator"` and `aria-orientation`. Both old selectors fail against the actual emitted element. As a result the intended one-pixel height/width and vertical stretch rules never apply. The source mismatch is confirmed; no browser pixel measurement is claimed.

Corrected only the shared selectors to `data-[orientation=horizontal]` / `data-[orientation=vertical]`. The intended border token, sizes, orientation default, roles, prop/ref passthrough and consumer markup remain unchanged. Production `DashboardSectionDivider` consumers include the horse care summary and stable member settings composition. `FieldSeparator` and the currently unreferenced `ui/item` separator also inherit the repair when rendered. No local divider patches or dormant-component deletions were made.

Read-only probe: `/tmp/paddock-separator-dom-probe.mjs`; output `/tmp/paddock-separator-dom-probe.log`. It renders the installed primitive with React's server renderer, parses the output into JSDOM, and checks selector matching. For both orientations, the old selector returns false and the actual `data-orientation` selector returns true. This is emitted-DOM evidence, not browser geometry verification. No class-string-only regression test was added. Scoped ESLint, Prettier, full TypeScript (`/tmp/paddock-remaining-wrappers-types.log`) and `git diff --check` passed; the parent owns aggregate build confirmation.
