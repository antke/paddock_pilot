## Confirmed findings

**P2 — percentage presentation decided domain urgency (source-corrected by parent).** At inspection, `DashboardPercentBadge` defaulted `warningBelow` to 75 and chose the destructive badge variant for every lower value. The style-lab Progress guideline explicitly says threshold decisions belong in feature components. Its alert-column specimen uses `<DashboardPercentBadge value={25} />` for Attention, Due, Planned and Gaps, which previously assigned destructive presentation to all four without a supplied domain threshold. This conflicts with the agreed distinction between ordinary state/value and error or urgent action. `DashboardPercentBadge` currently has only `StableDesignGuidelines.tsx` as a direct consumer; no live product metric defect is claimed. The parent applied the bounded correction in `DashboardBadges.tsx`: Percent now defaults to `secondary`, with an explicit `variant` available for genuine domain meaning; unused `warningBelow` was removed. This worker reread the resulting source and confirmed no remaining `warningBelow` consumers with `rg`. `Progress` still owns progress semantics; count badges were unchanged. No new browser or individual badge-variant test result is claimed.

**P3 — four-metric strip dividers do not account for two-column rows (source-corrected by parent).** `DashboardMetricStrip` defaults to four columns, implemented as two columns from `sm`/`md` until four at `xl`. `dashboardMetricStripItemClassName` applies left border/inset to every item except `:first-child`. Consequently the third item, first in the second row at the intermediate breakpoint, retains a leading divider/inset while the first item does not. This is a deterministic source mismatch between the grid recipe and divider recipe, not a measured screenshot defect. Exact current strip consumer: `DashboardCareOverview.tsx` → four `OverviewMetric` children with `stripItem={{ inset: 'compact' }}`. That exported composition has no current static application consumer. The parent subsequently moved divider/inset ownership to the strip, matching three/four-column row starts and the chosen breakpoint. Generated CSS contains the matching rules; two-column/four-column browser geometry remains unverified. No local consumer patch was made.

No broader shared-style ownership failure was confirmed in these files. Apart from the parent’s percentage-badge correction, the findings and inventory remain read-only. The parent subsequently corrected the shared strip row-boundary rules; see [metric/progress review](metric-progress-source-2026-09-19.md). Responsive browser geometry remains open.

## Global ownership and intentional composition

`src/styles.css` defines the approved Alegreya Sans body/UI token and Alegreya display/serif tokens. These owners consume token classes (`font-display`, `font-sans`, `font-serif`, semantic foreground/background/border colors), not raw replacement fonts or ad hoc hex palettes. `dashboardChrome.ts` centralizes flat/cards/soft treatment. `ActionGroup`, `Badge`, `InlineForm`, `Card` and `Separator` remain lower owners for their respective behavior and material recipes.

The flat `DashboardSectionCard` explicitly removes Card border/radius/background and internal horizontal padding while retaining a quiet bottom divider. That is the named domain owner's approved default, not a reason to remove all Card styles globally. Likewise, grids, rail widths, typography scales and long-token wrapping are purposeful shared layout decisions. `AnalysisHorseTab`'s urgent metric override expresses actual domain urgency using destructive tokens; it is not interchangeable with the PercentBadge's former blanket numeric threshold. Landing CTA branding is deliberate composition, not evidence that every product section should inherit an inverse surface.
